# Daily English 的 AI 能力规划

- 最后更新：2026-11-19
- 状态：**提案**（未排期，供 M4 / V2 排序参考）
- 关联：[产品方向](PRODUCT.md) · [架构](ARCHITECTURE.md) ·
  [技术债](TECH_DEBT.md) · [当前看板](PROGRESS.md)

> 这份文档只回答一个问题：**AI 还能怎么用，才真的让用户学会英语**。
> 不谈界面、不谈打包，只谈「AI 在学习闭环里承担什么角色」，以及为了承担这些角色
> 需要的最小改动。每条建议都标注了成本、落库影响、验收标准与风险，
> 可以直接当任务书拆。

---

## 0. 一句话结论

现在的 AI 是**内容工厂**：它负责把材料生产出来（文章、释义、题目、评分）。
而英语学习的瓶颈从来不是"没有材料"，是**主动回忆 + 被纠正 + 材料刚好贴住当前水平**。
后面两件事，AI 有别的工具替代不了的独占优势（判开放文本、给针对性反馈），
但项目目前只用了不到两成。

结论：**下一步不该再横向加功能，而该把 AI 从"生成器"改成"有记忆的陪练"** ——
让模型知道用户昨天错在哪，让用户先输出再被纠正，把建议变成下一周的具体约束。
按投入产出排，只有一件事必做：**复习环节加入"先写后判"**（见 P0-1）。

## 1. 现状盘点：AI 现在在做什么

全部调用都走 `AIClient`，都带 `task` 标签并落 `ai_calls`（见 ARCHITECTURE 6.23）。

| # | 任务 | 调用点 | 一次闭环里的次数 | 模型承担的角色 |
|---|---|---|---|---|
| 1 | 水平测评评分 | `assessment_service` | 1 | 判主观题（翻译）+ 定级 |
| 2 | 每日文章生成 | `article_service` | 1（校验失败 +1） | 写作者 |
| 3 | 查词 | `dictionary_service` | 1 / 词（缓存命中 0） | 词典 + 记忆法编辑 |
| 4 | 记忆方法 | `dictionary_service` | 0~1（按需） | 记忆法编辑 |
| 5 | 阅读反馈调级 | `level_feedback_service` | 2（定级 + 重写文章） | 评级 + 重写 |
| 6 | 阅读检测 | `reading_quiz_service` | 2~6 | 出题 / 审题 / 盲评 / 讲评 |
| 7 | 每周复盘 | `weekly_review_service` | 1 / 周 | 数据分析师 + 建议者 |
| 8 | 复习求助 | `review_help_service` | 1 / 次「忘记/模糊」 | 教练 |

一天常态约 **6~10 次调用**（文章 1、查词 2~4、检测 4~6），
检测是最重的一段：两轮出题 + 两轮审题 + 盲评 + 讲评，最坏 6 次。

三个结构性事实，决定了现在的天花板：

1. **全部无状态。** 每次调用只带 prompt 里现拼的少量画像（等级、薄弱点、最近标题）。
   模型不知道用户第 5 次忘记 `resilient`，也不知道上次检测错的是推断题还是细节题。
2. **AI 只判"它自己生成的东西"。** 检测里的短答是 0/1，产出题是 0/1，
   除此之外，用户**写出来的英文从来没有被逐句改过**。
3. **建议不落地。** 每周复盘给完建议就结束了，下一周的文章生成拿不到"这周该练什么"。

值得肯定的地方也要说清楚，这些别动：所有产物都落成本地结构化数据（文章、释义、
题目、证据），所以可缓存、可离线、可解释、可导出 —— 这是把 AI 用对的底子。

## 2. 核心判断：三个缺口

### 缺口一：没有记忆（stateless）

现在的"个性化"是把 `profile.weaknesses` 拼进 prompt 的一行字。信息量约等于零：
"学术词汇、长难句"这种标签对模型没有约束力，因为它不知道具体是哪些词、错了几次。

真正有约束力的是**结构化的近期证据**：你最近 7 天在 `affect/effect` 上错了 3 次；
你的错因 60% 是推断题；你上周说要练从句，但产出题里从句仍然出错。

### 缺口二：没有产出验证（只做再认，不做提取）

复习页是"看词 → 翻面 → 选 1~4"。这是**再认（recognition）**：看到英文能想起中文，
不代表能把它用出来，更不代表拼得对。而 SM-2 的 `ease` 和 `interval` 完全由这个
自评驱动 —— 也就是说，**调度算法的输入是用户的自我感觉**，而不是任何客观证据。
间隔重复的有效性建立在"提取成功/失败"这个信号上，自评把信号污染得最厉害。

这是当前产品最大的学习效率漏洞，也是最容易补的一处：让用户先写一个答案
（拼写 / 造句 / 中译英），再给评分。写对写错，本地能判一部分，剩下的只有 AI 能判。

### 缺口三：输入不"刚好难一点"（i+1 只有意图，没有测量）

产品定位写的是 i+1，实现上是"CEFR 等级 = B1"。但同样的 B1，生词密度可以从 3% 到
15% —— 后者根本不是 i+1，是 i+5。现在没有任何本地指标能发现这件事，
只能靠模型自觉，校验也只查词数和 `target_words` 是否出现。

好消息：项目已经有 `repair_note` 重试通道（校验失败把原因喂回模型重写）。
只要本地能算出"这篇太难"，就能复用这条通道，**不增加任何额外调用**。

## 3. 学习科学对照

| 原则 | 项目现状 | 缺口 |
|---|---|---|
| 可理解输入（i+1） | 按 CEFR 生成，靠模型自觉 | 无本地密度测量 |
| 检索练习 > 重复阅读 | 复习是看卡片回忆 | 偏再认，缺拼写/造句 |
| 间隔重复 | SM-2，可解释、可离线 | 输入信号是自评 |
| 产出性练习 + 反馈 | 检测里的短答/改写（0/1） | 无逐句纠错，无回译 |
| 精加工（elaboration） | 单词记忆方法（词根/联想） | 只有语义，没有"为什么用这个不用那个" |
| 计划 → 执行 → 回顾 | 每周复盘只到"回顾" | 建议没有变成约束 |

## 4. 建议（按优先级）

优先级只看两件事：**对学习效果的直接影响**、**改动是否小到能在一两天内完成**。
P0 = 建议下一轮就做；P1 = 有价值但可以等；P2 = 工程优化，效果不直接。

### P0-1 复习改成「先写后判」（最高优先）

**问题**：四档评分是自评，SM-2 拿到的是感觉不是证据；用户从不写英文。

**做法**：卡片翻面后，默认加一个**拼写回忆**输入框（看到中文义 + 首字母提示，
写出英文原形），再加一个可选的**造句**入口。

- 拼写：本地先判（归一化大小写/去空格 → 与 `lemma` 比对），不调 AI；
- 造句 / 拼写判不了：才调 AI，返回结构化的三件事 —— 意思对不对、语法/搭配错在哪、
  建议评分；
- **最终评分仍由用户点**，AI 只给 `suggested_rating`，且界面显示"AI 认为你更像『模糊』"；
- AI 失败/离线 → 直接退化为现在的四档自评，不阻塞复习（这是硬要求）。

**为什么这能让 SM-2 变准**：`rating` 从"我觉得"变成"我写出来对不对"，
调度才能真正跟着提取强度走。顺便把"复习页不能离线"这个风险卡死 —— 本地判分兜底。

**数据**（schema v8，只 `ADD COLUMN`）：`review_logs` 加
`answer_text TEXT`、`verdict TEXT`（`correct / partial / wrong / skipped`）、
`suggested_rating INTEGER`。现有导出自动带上。

**成本**：默认只做拼写（0 次调用）。造句按天 20 个词、其中 20% 用造句 ≈ 4 次/天。
可以加"本次不再提示造句"降低打扰。

**验收**：
- 离线全流程可走完（拼写判分 + 自评）；
- AI 超时/报错时评分照常记录，`verdict` 落 `skipped`；
- `review_logs` 已有数据不受影响，导出包含新列。

**风险**：复习变慢、变重。对策 —— 拼写是单行输入框 + 回车提交，不强制造句；
连续 3 次答对同一个词，自动跳过输入（只翻面确认）。

### P0-2 i+1 改成「本地可测」（复用现有重试通道）

**问题**：生词密度不可控，"B1" 是一个很宽的区间。

**做法**：加一个纯本地的可读性指标模块 `services/readability.py`（无 AI、无网络）：

1. `assets/wordlists/` 放一份**许可明确、可随仓库分发**的词表（例如 NGSL；
   **不要**直接打包 Oxford 3000 等受版权保护的词表，打包前先核对许可）。
   可选的替代方案是 `wordfreq` 这类库，但要确认它不把依赖拖得太重；
2. 近似"已知词集合" = 高频档（前 N 词）+ 用户 `interval_days >= 30` 的词
   + 用户 `in_vocabulary = 1` 的词；
3. 生成后算三个数：**未知词比例**、**目标词覆盖率**、**句子长度分布**（平均/最长）；
4. 超阈值 → 组装成 `repair_note` 走已有的"重试一次"路径；不额外调用。

**收益**：把"模型说这是 B1"换成"这篇对**你**确实只难一点点"。同时这份指标可以
直接显示在阅读页（"本篇 8% 生词，4 个目标词"），用户对难度的预期会准很多。

**数据**：`articles` 加 `metrics_json TEXT`（未知词比例/句长/覆盖率）。

**成本**：0 次额外 AI 调用（复用重试）；本地计算 10ms 级。

**验收**：纯函数可单测（给定词表与文本 → 指标）；阈值可配置；
指标只用于"重试判断 + 展示"，**不**用于改等级（等级仍由证据链决定）。

**风险**：词表覆盖不全导致误判。对策 —— 词表缺失的词按"未知"计但给一个宽容系数，
阈值偏保守（宁可不重试，也不要因为误判反复重写烧 token）。

### P0-3 学习者记忆档案（learner memory）

**问题**：每次调用冷启动，模型对你的了解只有一行 `weaknesses`。

**做法**：新建一张很小的表 `learner_memory`，存**可执行结论**而不是散文：

```
kind: 'error_pattern' | 'preference' | 'focus'
text: '推断题反复出错：只读字面，没注意作者态度词'   （≤ 80 字）
evidence_count: 3
updated_at: ...
```

- **来源不许让 AI 自由发挥**：每周复盘时，把**本地统计**（`quiz_calibration` 的
  错因分布/技能正确率、`review_logs` 里重复忘记的词、`level_evidence`）交给 AI，
  让它压缩成 ≤ 8 条结论；用户可以在复盘弹窗里删掉不认同的；
- **注入有硬上限**：所有 prompt 增加一个统一段落 `【学习者档案】`，总长 ≤ 300 token，
  且**按任务过滤**（查词只带 `preference/focus`，出题带 `error_pattern`）；
- 注入逻辑集中在 `prompts.py` 的一个 builder 里，各任务调用它，别各自拼字符串。

**成本**：0 次额外调用（复用每周复盘那一次），但**所有任务**的针对性都提升。

**验收**：档案为空时 prompt 与现在完全一致（不能因为新功能破坏现有行为）；
单测覆盖"按 kind 过滤"和"超长截断"。

**风险**：AI 总结漂移、注入过长挤占正文。对策 —— 条目上限 + 证据计数
（`evidence_count < 2` 不注入）+ 用户可删。

### P0-4 一次调用多产出：文章自带「教学包」

**问题**：一天 1 次文章生成，却只换来正文 + 标题 + 几个目标词，信息密度偏低。

**做法**：同一个 JSON 契约里加可选字段：

```
glossary: [{"word": "...", "sense": "语境义（中文）"}],   // 3 条
grammar_point: {"point": "非谓语作状语", "sentence": "原文中的例句"},
discussion: "一个能引发回答的开放问题"                      // 供检测出题复用
```

缺失时不校验、不报错（可选字段）；`max_tokens` 从 4000 上调。

**收益**：阅读页可以显示"本篇语言点"；检测出题时可以少一次冷启动；
成本几乎不变（输出多 200~400 token）。

**验收**：旧缓存文章（无这些字段）正常显示；字段缺失不触发重试。

**风险**：JSON 变长，失败率上升。对策 —— 字段全部可选，且只对"新生成"生效。

### P1-1 查词从「查一次」到「追问」

**问题**：缓存 key 是 `lemma`，同一个词在新语境会命中旧释义 —— 但语境义可能不同
（`charge` 可以是"收费/指控/冲锋"）。这是正确性 bug，不只是体验问题。

**做法**：`words` 之外增加 `word_senses`（`word_id + context_hash + meaning_cn +
example_en`），查词先按"原形 + 语境指纹"命中；释义卡加两个入口：

- 「这里为什么是这个意思」→ 一次调用，讲清上下文如何决定义项，结果缓存到 sense；
- 「容易和谁混」→ 易混词辨析（`affect/effect`、`adapt/adopt`），也缓存。

**成本**：只有用户点才调用，通常 1~2 次/天。

**验收**：同一词在不同句子查两次，得到不同 sense 且都留缓存；
旧词条（无 sense）走原路径不报错。

### P1-2 回译：把中文译文翻回英文，逐句对照

**问题**：用户几乎没有"被逐句纠错"的机会，而这正是 AI 最擅长、最不可替代的一件事。

**做法**：阅读完成后挑 2~3 句，给中文译文，让用户写英文；AI 与原句对比，
按 **语法 / 用词 / 搭配** 三类标出差异并给改写。不要求"标准答案"，只要求
"能表达同样意思的更自然说法"。

**为什么选它**：素材就在今天读过的文章里（无版权、无断网问题、语境已熟悉），
评估标准明确（原文就是参考答案），用户获得感最强，一次调用覆盖多句。

**数据**：可以扩展 `reading_quizzes.productions_json`，也可以独立表
`translations`；建议先走独立入口，避免把检测的调级逻辑搅进来。

### P1-3 兑现「多模型槽位」（产品决策 5 已预留，一直没做）

**做法**：`AIConfig` 增加一组可留空的 `tools` 配置；留空则全部回落主模型。
路由做成一张集中表（放在 `app_context.py` 或新 `model_router.py`）：

| 任务 | 路由 | 理由 |
|---|---|---|
| 查词 / 记忆方法 / 审题 / 盲评 | tools（便宜快） | 单点判断，质量容错高 |
| 文章 / 出题 / 讲评 / 复盘 / 反馈调级 | 主模型 | 长文本与判断质量敏感 |

**收益**：成本可能降一半，查词延迟明显下降（查词是交互最频繁的调用）。
`ai_calls.model` 已有列，天然能做前后对比。

**风险**：配置复杂度。对策 —— 设置页放在"高级"折叠区，默认不展示；
只允许"留空回落"，不引入第二套协议。

### P1-4 每周复盘 → 下周计划 → 生成约束

**问题**：复盘给完建议就结束，下一周的文章拿不到任何约束。

**做法**：复盘输出带结构的 `plan`：

```
{"focus_grammar": "定语从句", "target_words": ["...", "..."],
 "target_topics": ["science", "culture"], "daily_minutes": 10}
```

写进数据库，下一周 `article_service` 生成时把 `focus_grammar` 拼进
`learner_focus`、`target_words` 拼进目标词通道 —— **不改 prompt 结构**，
只改传参。周末复盘时再本地算一次"计划完成率"（目标词复现数、语法点覆盖数）。

**收益**：第一次形成真正的"计划 → 执行 → 回顾"闭环，AI 建议开始有约束力。

| 项 | 说明 | 注意 |
|---|---|---|

## 5. 成本模型（量级估算，不是账单）

单日常态 6~10 次调用。真正贵的不是"次数"，是**失败重试**和**超长输出**：

| 场景 | 量级 | 备注 |
|---|---|---|
| 一天常态 | ~8 次调用 | 文章 1 + 查词 2~4 + 检测 4~6 |
| 一次完整检测 | 4~6 次 | 两轮出题 + 两轮审题 + 盲评 + 讲评 |
| 文章校验失败重试 | +1 次全文生成 | 输出 ~4000 token，是最贵的一次 |
| P0-2 上线后 | **-1 次（期望）** | 提高一次成功率，减少重试 |
| P0-1 上线后 | +0~4 次 | 默认拼写本地判，只有造句才调 AI |
| P1-2 回译 | +1 次/篇 | 多句合并成一次调用 |

结论：**别急着省钱，先省重试**。P0-2 是唯一能"既提质又降本"的一项，
它比换便宜模型更直接 —— 后者只降低单次价格，前者减少失败次数。

## 6. 数据模型草案（schema v8）

全部是 `ADD COLUMN` / `CREATE TABLE`，**不重建表**（沿用 ARCHITECTURE 6.16 的迁移纪律）：

| 表 | 改动 | 用途 |
|---|---|---|
| `review_logs` | `+answer_text, +verdict, +suggested_rating` | P0-1 先写后判 |
| `articles` | `+metrics_json` | P0-2 生词密度/句长 |
| `learner_memory`（新） | `id, kind, text, evidence_count, created_at, updated_at` | P0-3 长期记忆 |
| `word_senses`（新） | `id, word_id, context_hash, meaning_cn, example_en, created_at` | P1-1 语境义 |

迁移规则不变：`_apply_schema()` 按版本 `ALTER TABLE`，加列前用 `PRAGMA table_info`
判断，重复启动幂等；导出在 `export_service.CSV_COLUMNS` 同步加列（新增表是第十二张）。

## 7. 实施顺序（建议）

| 迭代 | 内容 | 估时 | 依赖 |
|---|---|---|---|
| A | P0-2 本地 i+1 指标 + `articles.metrics_json` + 重试接入 | 1 天 | 词表许可确认 |
| B | P0-1 复习拼写/造句 + `review_logs` 扩展 + 离线兜底 | 1.5 天 | A 的纯函数习惯 |
| C | P0-3 learner memory + 统一注入段（复盘时生成） | 1 天 | 每周复盘已有 |
| D | P0-4 文章教学包 + P1-1 语境义追问 | 1.5 天 | — |
| E | P1-3 tools 槽位与路由 | 1.5 天 | 设置页改动 |
| F | P1-2 回译练习 | 1~2 天 | B 的判分逻辑 |

每个迭代的固定要求（与项目约定一致）：纯函数优先、AI 全部 mock、
AI 失败必须可降级、不改 `services` 对 PySide6 的零依赖、`prompt` 改动同步升
`PROMPT_VERSION`、完成后更新看板并在 HISTORY 追加记录。

**如果只能做一件事**：做 B（P0-1）。它直接改的是 SM-2 的输入信号，
是这份文档里唯一一个"改了之后整个复习闭环会变准"的改动。
M4 的深色模式、安装器优先级都应该排在它后面。

## 8. 明确不建议做的

| 不建议 | 理由 |
|---|---|
| 让 AI 决定 SRS 调度 | 不可解释、不可离线、结果不可复现；调度规则应该留在 `srs.py` 纯函数里 |
| 让 AI 自由生成测评题库 | 破坏"结果可复现、可比较"（产品决策 2）；固定题库 + AI 只评分是对的 |
| 让 AI 直接改等级 | 现有"建议 + 用户确认 + 连续证据"已经很克制，不要再放松 |
| 口语对话陪练 / 发音评分 | 需要语音识别 + 评分模型，工程量远大于收益，V2 之外 |
| 把缓存改成每次实时调用 | 成本爆炸且离线不可用；缓存是本项目最正确的设计之一 |
| 用 AI 生成"学习报告"堆在首页 | 没有对应动作的报告等于装饰；要报告先要计划（P1-4） |

## 9. 怎么判断这套东西真的有效

别用"生成了多少 token"衡量，用这几个可本地计算的指标（都可离线算）：

| 指标 | 含义 | 数据来源 |
|---|---|---|
| 5 分钟闭环完成率 | 打开 → 读完 → 复习完的比例 | `daily_stats` |
| 生词首次通过率 | 第一次复习 `rating >= 3` 的比例 | `review_logs` |
| 生词回炉率 | 复习过的词在后续文章里再次出现的比例 | `articles.target_words` |
| 检测得分趋势 | 同等级下的得分变化 | `reading_quizzes` |
| 计划完成率 | 上周 `plan` 的覆盖情况 | 复盘 plan + 文章指标 |
| 重试率 | 文章/检测因校验失败重试的比例 | `ai_calls` |

这些指标在 P0-1/P0-2 上线后就能算，不需要埋新点。它们也是未来校准
`level_estimator` 阈值（技术债里反复提到的"经验值"）的真实数据来源。
