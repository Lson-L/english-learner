当前能力（M3.19 后）：配置 AI → 测评 → 每日文章 → 双击查词 / 悬浮释义卡 →
加入生词本 → 阅读检测（两轮自适应 + 盲评 + 本地后验 + 英译中产出题）→ 每周复盘；
SM-2 复习可完全离线：每日目标默认 20 个，当天只取「目标 - 今日已完成」，
每 10 张一个检查点，卡片页可随时「结束本轮」，未做完的到期词留在积压里可加练；
拼写输入默认关闭，先只做看词回忆；在「设置 → 复习」打开后，卡片形态由系统
自动编排：新词先「看词回忆」，熟悉后加入「拼写回忆」，上次忘记/模糊或拼错的词
排成「看词 + 拼写」双阶段卡（同一张卡先认义、翻面后遮住词形再默写一次），
两种模式在同一次会话里穿插；
拼写看中文释义输入英文，本地判分只给评分建议，不改调度；
每次复习都会把拼写答案、判定（correct / near / wrong / skipped）与编辑距离
写入 `review_logs`，调度仍只由用户确认的评分决定；新加入生词本的词从明天开始
第一次复习，避免读文章加词后当天队列立刻膨胀；
M5.2 起每次 AI 调用前会带上一份本地派生的学习者记忆（等级 / 近期错因 /
反复忘记与拼错词 / 到期积压 / 上周计划，≤200 token），空数据时 prompt 与之前
逐字节一致；上周复盘重点会回流为文章生成的软约束与本次复盘的“计划完成度”；
M5.3 起每篇新文章会用内置静态词表算出“生词比例 / 平均句长 / 目标词覆盖”
写入 `articles.metrics_json`，阅读页 meta 行展示生词比例与目标词数，
超阈值标记“偏难”（默认只告警，可在 `config.json` 的 `readability` 段
开启强制重试）；旧文章没有指标时正常显示；
M5.4 起阅读页可做回译练习：本地从当天文章抽 3 句（优先含目标词、长度适中），
AI 译成中文后用户写回英文，一次批量批改给逐句 0/2 分、最小修改、原因与
错误类型；题目按文章缓存、重复打开不重复请求，结果写 `writing_attempts`
并可导出，错误类型进入学习者记忆供后续文章覆盖；练习不影响等级与 SRS；
M5.5 起设置页新增「学习效果（近 30 天）」：生词首次通过率、词回炉率、
上周计划完成率、文章 / 检测重试率与同等级检测得分趋势，全部由本地记录
聚合，0 次 AI 调用，空数据时显示 “—”；
M6.1 起阅读查词不再每个词都干等 AI：文章生成时顺带产出 8~15 个难词的
语境义（写入查词缓存），打开文章后还会在后台用一次批量请求预查 10 个左右
对当前等级偏难的词；双击这些词直接出释义，预取只补缓存、不进生词本，
失败静默。可在「设置 → 阅读」关闭预取；
M6.2 起阅读检测的选择题和摸底测评一样，选项之后多一个「不知道」：不会的题
可以直接选它并写明哪里没看懂（单词不认识 / 句子太长等），不用瞎猜；
「不知道」是有效作答，本地按答错计入正确率与等级证据，补充说明会交给
AI 讲评和盲评作为错因线索；第一轮答案锁定时说明也一并保留；
M6.3 起把预置的简释词加入生词本后，后台会自动按完整查词再补一次例句与
记忆方法（独立线程，不打断阅读），完成后原地刷新释义卡与词条；补全失败
保留原简释，不影响已加入生词本与高亮；
设置页可导出 JSON / CSV、查看 AI 调用记录与运行日志；每次启动会自动把
`data.db` 备份到 `backups/`（`data-YYYYMMDD.db`，保留最近 7 份，迁移前执行），
「设置 → 数据导出与备份」可直接打开备份目录；换电脑时用「导出数据库 /
导入数据库」整库搬运（导入先校验与暂存，随后可选立即重启或回退；重启时
自动备份本机库再替换，旧库版本过高或损坏会拒绝）；
关闭窗口时会记住大小 / 位置 / 最大化状态（`config.json` 的 `window` 段），
下次启动原样恢复；换显示器后旧位置不可见时由 Qt 自动挪回可见区域。
启动时先显示轻量遮罩（`gui/splash.py`），再导入 openai SDK 与全部页面 /
弹窗模块；`import english_learner.app` 从约 1.5s 降到 0.3s，
重依赖加载期间能看到阶段文案与进度，不再出现“双击没反应”。
侧边栏新增「统计」页（2026-11-24）：26 周打卡热力图、累计生词 / 阅读 / 复习
曲线、近 30 天堆叠柱、词汇掌握分段条、按等级的检测得分折线与 12 个成就徽章；
全部由 `services/stats_overview.py` 从本地 SQLite 聚合，0 次 AI 调用，
图表用 QPainter 自绘并跟随两套主题换色。
所有 AI 请求都带任务标签并写入 `ai_calls`（token / 耗时 / 错误，
不保存提示词与模型回复）。

## 3. 快速开始

```bash
# 安装依赖（PySide6 与 openai 都是核心依赖）
uv sync

# 启动（首次会进配置向导）
uv run english-learner
uv run python -m english_learner            # 等价

# 已有配置时强制重新配置
uv run english-learner --reconfigure

# 测试 / 检查
uv run pytest -q
uv run ruff check src/english_learner tests
uv run ruff format src/english_learner tests

# 打包成单文件 exe → dist/DailyEnglish.exe（裁剪后约 36MB，双击即用）
uv run pyinstaller --noconfirm --clean DailyEnglish.spec

# 目录版（启动更快、杀软误报更少）→ dist/DailyEnglish/DailyEnglish.exe
DAILYENGLISH_ONEDIR=1 uv run pyinstaller --noconfirm --clean DailyEnglish.spec
```

配置文件位置（Windows）：`%APPDATA%\EnglishLearner\config.json`
日志：`%APPDATA%\EnglishLearner\logs\app.log`
想重演首次启动：删除上面的 `config.json`，或加 `--reconfigure`。

> 本机 `uv run pytest -q` 偶发在 Qt offscreen 退出阶段返回 127（用例仍全部通过）；
> 可尝试 `uv run pytest -q -p no:cacheprovider`。这是本机 Qt 清理与 pytest 的
> 兼容问题，与业务代码无关；判断结果看用例输出，不要只看退出码。

## 5. 下次会话开工

新会话不需要复制长指令，直接说 **「完成本次开工计划」**（或「开工」「继续 M6」）。
AI 按以下固定协议执行，规则细节以 `CLAUDE.md` 与 `AI_TASKS.md` 为准：

1. 读本文件看板，确认当前基线与下一项；
2. 读 [AI_TASKS.md](AI_TASKS.md)，取**第一个未完成里程碑**，按任务卡的改动点与验收执行；
3. 默认一次只完成一个里程碑；完成、验证并汇报后停下，等用户说「继续」再做下一个；
4. 收尾三件事：补测试并通过 → 更新本文件看板状态 → 在 `HISTORY.md` 追加交付记录；
5. 任务卡与代码现状不符、或需要超出任务卡范围时，先停下说明差异，不要静默改计划。

开工前如需确认基线，可运行 `uv run pytest -q` 与
`uv run ruff check src/english_learner tests`；用户未要求时不主动跑打包 / 构建。
